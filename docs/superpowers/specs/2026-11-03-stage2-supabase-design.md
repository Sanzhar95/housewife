# Этап 2: «Домашняя кухня» на Supabase — спецификация дизайна

Дата: 2026-11-03 · Статус: **на утверждении у Санжара** · Следующий шаг после утверждения: подробный план реализации (skill writing-plans).

## 1. Цель и принятые решения

**Цель.** Проверить продуктовую часть «Домашней кухни» на своей платформе: быстрый отклик, вход по логину и паролю, семья из нескольких людей, возможность дать доступ тестовым семьям. Инфраструктурная «полировка» откладывается.

**Сценарий.** Когда я нажимаю «Готовить» на телефоне, хочу, чтобы экран отреагировал сразу, а муж видел те же данные на своём телефоне, без Google Таблицы.

| Решение | Выбор |
|---|---|
| Для кого | Сначала наша семья (2 человека), другие семьи позже (вариант «Б»): схема с `household_id` сразу, интерфейса «создать свою семью» пока нет |
| Где считается логика | В браузере (`logic.js`, порт из `Code.gs`); база: `get_state()` и запись одной транзакцией с проверкой версии (`apply_changes`), RLS |
| Вход | Логин (e-mail) + пароль, без подтверждения почты, без SMS и SMTP |
| Регистрация | Только по одноразовой ссылке-приглашению (7 дней) |
| Отклик | Оптимистичный: экран обновляется сразу, запись идёт в фоне по очереди; флаг `OPTIMISTIC=false` переключает на «ждать запись» |
| Хостинг | Netlify (статика) + Supabase (Frankfurt, Free). Проект создан |
| Дизайн | Как в `Index.html`: те же токены, классы и хелперы (`h()`, `field()`, `modal()`) |
| Не входит в этап 2 | Уведомления (e-mail, Telegram), автокопии, realtime, «создать свою семью», восстановление пароля по почте, офлайн-запись |

## 2. Архитектура

```
iPhone / браузер ──► Netlify (статика: index.html, logic.js, db.js, auth.js, api.js, sw.js)
        │
        └──► Supabase (Frankfurt)
              ├─ Auth: логин+пароль, сессия в localStorage, обновление токена
              └─ Postgres: таблицы + RLS; функции get_state(), apply_changes(), create_invite()
```

- `call(fn, ...args)` в `index.html` (стр. 618–622) вызывает `API[fn](...args)`; `act()` не меняется. `API` возвращает тот же объект состояния `S` (с полем `notice`).
- Одно действие: `next = logic[fn](clone(S), ...args)` → экран показывает `next` → `db.commit(base, next)` отправляет разницу `apply_changes(версия, изменения)`.
- Очередь записи последовательная. При конфликте версий (второй телефон успел раньше): `get_state()`, повтор того же действия на свежих данных, повторная запись. Если повтор невозможен (логика бросила ошибку) или нет сети: красный тост, откат к свежему состоянию.
- Данные обновляются при возвращении в приложение (`visibilitychange`), кроме случаев, когда открыт диалог или идёт запись.

**Структура репозитория**

```
apps-script/   Code.gs, appsscript.json          (архив, эталон для тестов)
legacy/        Index.html                        (текущий клиент, эталон)
public/        index.html, logic.js, db.js, auth.js, api.js, sw.js, manifest.json,
               vendor/supabase.js, icons/, config.js (генерируется, не в git)
supabase/migrations/   001_init.sql ...
tools/         migrate.js, backup helpers
tests/         сравнение со старым кодом, RLS, сверка миграции
docs/superpowers/{specs,plans}/
```

Файл `apps-script/api-patch.gs` из этапа 1 удаляется. `.gitignore` обязателен (`.env`, `public/config.js`, `*.xlsx`, `.DS_Store`, `*.zip`).

## 3. Вход, сессия, семья

- **Вход:** `signInWithPassword(email, password)`. E-mail приводится к нижнему регистру и обрезается. Пароль от 8 символов (проверка на клиенте и настройка в Supabase).
- **Сессия:** хранит supabase-js в localStorage (`persistSession` по умолчанию включён). По документации, access-токен живёт 1 час, refresh-токен не истекает по сроку, но одноразовый; тайм-аут по неактивности есть только на платных тарифах. Поведение на iPhone в режиме «На экран Домой» проверяется руками (см. п. 10).
- **Регистрация по ссылке:** ссылка вида `https://<сайт>/#/join/<токен>`. Токен берётся из части после `#`, вызывается `signUp(email, password, {options:{data:{invite: токен}}})`.
  - Триггер `handle_new_user` (после вставки в `auth.users`) проверяет токен (по хэшу, срок, не использован). При успехе добавляет человека в семью, при `kind='new_family'` создаёт семью, помечает приглашение использованным и удаляет токен из метаданных. При неудаче бросает исключение, и регистрация откатывается целиком.
  - Регистрация в Supabase включена («Allow new users to sign up»), поэтому защита держится на триггере. «Confirm email» выключен, письма не отправляются.
  - Если на спайке (п. 10, R1) триггер окажется неудобным (ошибка клиенту непонятна), запасные варианты: официальный hook «Before User Created» (по документации доступен на Free) или Edge Function с admin API.
- **Приглашения:** `create_invite()` доступна владельцу семьи, возвращает токен один раз, хранится только его хэш. Первая семья: `admin_new_family_invite(name)` выполняется в SQL Editor, не доступна ролям `anon` и `authenticated`. Тестовые семьи создаются так же.
- **Один человек: одна семья** (`unique(user_id)` в `members`). Роли: `owner`, `member`.
- **Смена пароля:** в ⚙️ при активной сессии (`updateUser({password})`). **Забытый пароль:** письма не шлём; сбрасывает владелец по инструкции в README (способ уточняется на спайке R3).
- **Тексты ошибок (по-русски):** «Неверная почта или пароль», «Ссылка не подходит: она уже использована или устарела. Попросите новую», «Нет связи. Попробуйте ещё раз», «Войдите заново» при истёкшей сессии.

## 4. База данных и защита

**Принципы.** Таблицы повторяют листы; ID остаются текстом из 8 символов (старые сохраняются без переименования); даты и `weekStart` хранятся строками `yyyy-MM-dd HH:mm` / `yyyy-MM-dd`, как в таблице; числа в `double precision`; ссылки между таблицами без жёстких внешних ключей (старые «хвосты» не должны ломать перенос). Первичные ключи составные `(household_id, id)`. Для сохранения порядка из листов у products, dishes, ing — столбец `seq bigint generated always as identity`.

| Таблица | Ключевые поля |
|---|---|
| `households` | `id uuid`, `name`, `week_start text`, `portions int null`, `email text null`, `tz text default 'Asia/Almaty'`, `version bigint default 0` |
| `members` | `household_id`, `user_id unique`, `role` |
| `invites` | `id`, `household_id null`, `kind ('join'/'new_family')`, `token_hash unique`, `created_by`, `expires_at`, `used_at`, `used_by` |
| `products` | `id`, `name`, `unit`, `stock`, `min_stock` |
| `dishes` | `id`, `name`, `note`, `type ('main'/'side'/'extra')`, `meals text`, `with_side bool`, `recipe_portions`, `times` |
| `dish_items` | `dish_id`, `product_id`, `qty`, `recipe_unit` |
| `plan` | `id`, `day`, `meal`, `kind`, `dish_id`, `side_id`, `done`, `done_at text`, `left bool`, `portions`, `from_id` |
| `purchases` | `id identity`, `when_str`, `product_id`, `qty`, `unit`, `total null`, `unit_price null` |
| `log` | `id identity`, `when_str`, `action`, `obj`, `details` |

**Чтение.** `get_state()` (security invoker, RLS применяется) возвращает одним запросом то, что сегодня возвращает `state_()`: `products, dishes, ing, plan, settings{email, weekStart, portions}, log` (последние 100, новые первыми), `purchases` (последние 3000, по возрастанию), плюс `version` и `me {email, role, household}` (для экрана настроек: кнопка приглашения только у владельца). Порядок: продукты/блюда/состав по `seq`; план по (день, приём, основное раньше доп.); журнал и приходы по `id`.

**Запись.** `apply_changes(expected_version, changes jsonb)` (security definer, `set search_path = ''`, имена с указанием схемы):
1. Определяет семью по `auth.uid()`; не участник: ошибка.
2. Блокирует строку семьи (`for update`), сверяет версию; не совпала: ошибка конфликта.
3. Применяет по каждой таблице `upsert` и `delete` по ключу, добавляет строки журнала и приходов.
4. Увеличивает версию, возвращает новую.
Всё одной транзакцией: при любой ошибке откатывается целиком (в Apps Script часть записей успевала сохраниться до сбоя).

**Права.** Права выдаются явно (опция «Automatically expose new tables» выключена, RLS-автовключение включено): `select` на таблицы данных для `authenticated` с политикой `is_member(household_id)`; прямой записи в таблицы данных нет; `revoke execute ... from public, anon`, `grant execute` на `get_state`, `apply_changes`, `create_invite` для `authenticated`. Ключ `service_role` в браузер и в репозиторий не попадает; публичный ключ (anon) безопасен благодаря RLS.

## 5. Клиент

- **`logic.js`** — порт предметной логики `Code.gs` (около 40 функций): единицы и форматирование, потребность и порции, подбор блюд, склад, остатки («хватает на N раз»), готовка, отмена, гарниры, «вчерашнее», импорт продуктов. Функции принимают состояние и возвращают новое состояние и `notice`. Заменяется: `Utilities.formatDate`/`tz_` → `Intl.DateTimeFormat` с `Asia/Almaty`, `Utilities.getUuid` → `crypto.randomUUID()`, `LockService` → версия, `MailApp`/триггеры/листы/миграции удаляются. Источники недетерминизма (`Math.random` в `shuffle_`, `id_`, `now_`) внедряются параметрами, чтобы тесты были повторяемыми. Перед каждым действием состояние клонируется глубоко и при ошибке выбрасывается; после действия данные нормализуются так же, как при сохранении и загрузке (`portions` 0, пустые строки, единицы состава).
- **`db.js`** — `get_state`, сравнение «было/стало» по ключам, `apply_changes`, очередь, повтор при конфликте.
- **`auth.js`** — экраны входа и регистрации, выход, смена пароля, приглашение.
- **`api.js`** — `API[fn]` с теми же именами, что вызывает клиент (26 действий, `getState`, `setIngredient`). Сигнатура `saveSettings(portions)` без e-mail.
- **Правки `index.html`:** `call()`; `init()` проверяет сессию до `getState`; при отсутствии сессии показывается экран входа (`body.anon` скрывает навигацию и кнопки шапки); настройки (стр. 894–911): убрать поле e-mail (896, 903–904, 908), добавить «Вы вошли как …», «Пригласить в семью», «Сменить пароль», «Скачать копию», «Выйти»; `cleanErr` переводит сетевые ошибки и ошибки токена; `setCell` (1693–1707) подключается к индикатору сохранения; тексты справки про почту и Google Таблицу (1999–2003, 2014) переписываются; убирается `<base target="_top">` (стр. 7); в `meta viewport` добавляется `viewport-fit=cover`.
- **Индикатор «сохраняется…»** — счётчик (не флаг), рядом с названием в шапке.
- **Excel.** `exportXlsx` на клиенте: файл собирается в браузере и отдаётся через Blob-ссылку (окно «Файл готов» сохраняется, к ссылке добавляется `download`). Как в старой выгрузке (`Code.gs` 1083–1108): жирная шапка с фоном `#ece8fc`, заполняемые столбцы (`fill`) с жёлтым заголовком `#ffd970` и ячейками `#fff6d1`, выпадающий список единиц в столбце `unitCol`, строка «Итого» жирная, закреплены строка и столбец. Бесплатная SheetJS стили и проверку данных не пишет, поэтому для записи используется ExcelJS (подгружается только при выгрузке), для чтения остаётся SheetJS. «Проверить на iPhone».
- **Общие расчёты.** Клиент сам считает `needMap`, `itemNeed`, `weekNeed`, `shoppingList`, `dishP`, `isLow`, `r3` и дублирует константы (стр. 489–502, 508, 576, 834–868). Сначала добавляется тест на совпадение этих функций с `logic.js`; после зелёных тестов клиентские копии заменяются вызовами общего модуля.
- **Попутное исправление:** на экране «Цены» (стр. 1832) граница «30 дней» считается через `toISOString()` (UTC), для Алматы вечером она сдвигается на сутки; собрать дату локально, как `todayStr`.
- **Service worker:** новый номер кэша, в оболочку добавляются `logic.js`, `db.js`, `auth.js`, `api.js`, `vendor/supabase.js`; запросы к Supabase не кэшируются.

## 7. Перенос данных

**Источник:** выгрузка «Домашняя Кухня.xlsx» (7 рабочих листов). Не переносятся: `Лист1` (пуст), `Неделя` (только шапка), `Неделя (архив)` (7 строк v1, уже перенесены в «План»). Файл xlsx не попадает в git.

**Состояние выгрузки на 2026-11-03:** продукты 46, блюда 34 (25 основных, 5 гарниров, 4 салата/доп.), состав 152, план 15 (2 «вчерашних», `weekStart` = 2026-11-02, приготовлено 0), журнал 251, приходы 55, настройки: `email`, `weekStart`. Все новые столбцы таблицы присутствуют, ссылки между листами целы.

**`tools/migrate.js`:** читает xlsx, строит то же состояние, что `load_()`/`state_()`, входит под новым аккаунтом (логин и пароль спрашивает при запуске, нигде не хранит) и отправляет данные через `apply_changes` без секретных ключей. Правила нормализации:
- ID, превращённые Google в число (в плане `35409132`), возвращаются строкой; нецелые числа (научная запись) заменяются новым ID с обновлением ссылок `from`.
- Даты Excel (дата-время без часового пояса, местное время Алматы) форматируются в `yyyy-MM-dd HH:mm`.
- Приходы по несуществующему продукту (`1447c4ad`) сохраняются как история и отмечаются в отчёте.
- Пустые значения: `Рецепт на, порций` и `Хватает на, раз` пусты у всех блюд, значит действуют значения по умолчанию (4 и 1).
- Повторный запуск отказывается работать в непустой семье (чтобы не дублировать приходы и журнал); как очистить для повтора, описано в README.

**Сверка (должна совпасть полностью):** число строк по каждому листу; остаток по каждому продукту; 6 продуктов «ниже или равно минимуму» (5 из них на нуле); 2 «вчерашних»; `weekStart`.

**Порядок:** 1) копия таблицы; 2) репетиция в тестовой семье за один вечер; 3) финальный перенос вечером после того, как жена перестала пользоваться старым приложением (выгрузка заново, запуск, сверка, ссылка-приглашение жене); 4) старая таблица и приложение остаются архивом минимум 30 дней. **Откат:** вернуться в старое приложение можно, но введённое в новом после переключения там не появится (переносится вручную из «Скачать копию»).

## 8. Хостинг и настройка

**Netlify:** репозиторий GitHub (приватный) → build command `node build.js`, publish directory `public`; переменные `SUPABASE_URL`, `SUPABASE_ANON_KEY` (`build.js` генерирует `public/config.js`). Если сборка падает из-за «secrets scanning» (Netlify также ищет похожие на секреты строки, а публичный ключ Supabase похож на JWT), в документации Netlify есть переменные `SECRETS_SCAN_OMIT_KEYS`, `SECRETS_SCAN_OMIT_PATHS`, `SECRETS_SCAN_SMART_DETECTION_ENABLED`. Библиотека `supabase-js` лежит в `public/vendor/` (зафиксированная версия).

**Ограничения бесплатных тарифов (по их страницам цен на 2026-11-03, перепроверить при настройке):**
- Supabase Free: 500 МБ базы, 2 активных проекта, **пауза проекта после недели без активности**, **автоматических копий нет**, запросы к API без лимита. Страховка: кнопка «Скачать копию» (JSON) и исходная выгрузка.
- Netlify Free: 300 кредитов в месяц, деплой в продакшен стоит 15 кредитов (это около 20 деплоев в месяц), трафик 20 кредитов за ГБ; при исчерпании проекты ставятся на паузу. Приватные репозитории организаций на Free не поддерживаются, про личные страница молчит. Запасной вариант: Cloudflare Pages (подготовлен в этапе 1) или ручной деплой папки `public/`.

**Настройка Supabase (один раз):** проект уже создан (Frankfurt, «Automatically expose new tables» выключено, автоматическое включение RLS включено). ## 9. Тестирование

## 11. Известные особенности старой логики (переносим как есть, чинить отдельным шагом)

1. `undoItem` возвращает продукты по текущему рецепту и порциям, а не по фактически списанному (если рецепт изменили после готовки, остаток разойдётся).
2. `cookDish` без `target` при `times > 1` выдаёт ложное «остатки не поставлены… следующую неделю».
3. `generateWeek` теряет невыполненные «вчерашние» строки старой недели.
4. `addLeftover` теряет текст уведомления о размещении остатков.
5. `setSide_` при `undefined` вместо `''` лишний раз пересчитывает и пишет в журнал.
6. `rerollItem` не сбрасывает `from` у строки.

Исправление этих пунктов делается после того, как сравнительные тесты зелёные, отдельными задачами.

## 12. Метрики теста концепции

Считаются по журналу `log` без отдельной аналитики. Сейчас в журнал пишутся: «Меню составлено» (`generateWeek`), «Приготовлено», «Приход», создание и изменение продуктов и блюд, замена гарнира после готовки. **Замены блюд в меню (`rerollItem`, `setItem`, `addItem`, `removeItem`) и открытия приложения в журнал не пишутся**, поэтому метрики «доля меню, принятых без замен» и «открытия в неделю» по нему не посчитать. Решение: после зелёных сравнительных тестов (п. 9.1, они сравнивают и журнал) отдельной задачей добавляются записи «Блюдо заменено» и «Меню открыто» (не чаще раза в час). До этого метрика «готовок через приложение за неделю» считается по записям «Приготовлено».
